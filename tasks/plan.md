# Завершение ДЗ 1 по AI-агентам

Актуализировано 2026-10-30 после возобновления работы. Цель — воспроизводимое
решение обязательной части с реальными измерениями, разбором ошибок и материалами
для сдачи. Требования перечислены в [docs/PLAN.md](../docs/PLAN.md).

## Подтверждённое состояние

- 145 вопросов: 125 исходных с документированными исправлениями и 20 новых.
  Проверка формата проходит для всех; вручную по источникам проверены 28 вопросов,
  остальные 117 исходных записей заново вручную не проверялись.
- Реализованы инструменты, ограниченный цикл, защита от повторов, учёт расходов,
  JSON-трейсы, продолжение запуска, пять конфигураций и генератор отчёта.
- 149 локальных тестов проходят. Чистый клон проверялся для предыдущей версии
  с 118 тестами, до интеграции Groq.
- Groq дал три правильных ответа на один и тот же вопрос в трёх профилях.
  Это проверка интеграции. Оценка расходов $0.0008115 не является списанием.
- Все пять обязательных строк отчёта — 0/145; свежесть Sonnet не измерена.
  Два реальных провала ещё не разобраны. Groq-изменения не закоммичены,
  существующий ZIP их не содержит; удалённый Git-репозиторий не настроен.

## Решения и порядок

1. Завершить проверку и оформление Groq; актуализировать инструкции и сохранить
   воспроизводимую версию. Параллельно проверить качество вопросов и источников.
2. Получить доступ к Sonnet 4.6. OpenRouter — уже реализованный вариант, но не
   требование задания. После вопроса пользователя о бесплатном доступе сначала
   проверить пробные кредиты OpenRouter/Anthropic; не предполагать, что их хватит.
   Прямой Claude API потребует адаптации клиента. Ключ хранится в локальном `.env`.
3. Выполнить маленький пилот с отдельными трейсами: проверить вызовы инструментов,
   формат финального ответа и наличие фактического `usage.cost`. Исправить выявленные
   проблемы до основного эксперимента и зафиксировать код.
4. Проверить Sonnet 4.6 без инструментов на всех 145 вопросах. Требование — не более
   20% правильных ответов (29 из 145). При непрохождении уточнять/заменять вопросы
   по источникам, сохраняя минимум 20 дополнений; после изменений начать новый
   согласованный эксперимент, не смешивая версии набора.
5. На принятой версии данных выполнить остальные четыре обязательные конфигурации.
   Результаты Sonnet повторно использовать через штатный `--resume` при неизменном
   коде, данных и настройках. Всего для пяти строк — 725 ответов на вопросы;
   число обращений к LLM больше из-за многошагового агента.
6. Проверить метрики, построить график, вручную разобрать два реальных провала
   по трейсам и сформулировать вывод, который действительно следует из результатов.
7. Проверить окончательный чистый клон, обновить архив и подготовить репозиторий
   для сдачи. Публикация зависит от выбранного пользователем репозитория;
   отправка преподавателю не выполняется автоматически.

Обязательные конфигурации: сильная без инструментов, дешёвая без инструментов,
дешёвая с поиском, дешёвая с поиском и чтением, средняя с лучшим набором инструментов.
Текущая реализация основного эксперимента использует OpenRouter с фактическим `usage.cost`.
Это выбор реализации: PDF требует измерения стоимости, но не предписывает провайдера
или поле `usage.cost`. Другой провайдер допустим при воспроизводимом расчёте;
субсидию/пробные кредиты и тарифную оценку нужно явно отличать от списаний.
Текущий Groq-путь остаётся отдельной диагностикой: расчёт по токенам не смешивается
с подтверждёнными расходами. Бонусы и личный агент из части 2 идут после обязательного
результата и не входят в текущий минимальный объём.

## Контрольные точки и риски

- До платного полного запуска: понятны источники вопросов, проходит пилот,
  нет утечки эталонов, выбран лимит расходов. Значение `$5` в README — ограничитель,
  а не обещание стоимости всего эксперимента; проверка происходит между запросами.
- До сравнений: критерий свежести выполнен, версия данных и кода зафиксирована.
- До сдачи: пять полных строк, известные расходы, два ручных разбора, чистый клон.
- Неизвестное списание или прерывание требует сверки учёта; нельзя удалять маркер
  и повторять запрос наугад. Отдельные пилотные каталоги имеют отдельные расходы.
- Wikipedia может не содержать нужную публикацию, а второй поиск ранее вернул
  антибот-проверку. Это проверяется пилотом; бонус не заявляется до рабочего сравнения.
