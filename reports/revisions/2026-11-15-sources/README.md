# Источники ДЗ 1 и раздельный учёт ошибок

Вторая локальная итерация, 15 ноября 2026. Новых обращений к моделям или внешним
сайтам не было; новые списания — **0**. Исходные результаты и ревизия P0 сохранены.
[Проверка: 690 тестов основной среды и 10 проверок Milvus](verification.md).

## Что изменено

Добавлен инструмент `official_search` и опциональный режим `cheap_official_sources`.
Он ищет по общему каталогу пяти издателей: ESA/Hubble, ESA/Webb, ESO, ALMA и Chandra.
Каталог содержит домены, без путей статей, ID вопросов, эталонов и цитат. Поиск
получает текст запроса и необязательный выбор издателя; по умолчанию ищет по всем пяти.

Один вызов выполняет один запрос DDG HTML. Из выдачи выбираются только ссылки
на официальные домены и их `www`-варианты, затем применяется лимит пяти результатов.
Неправильные и чрезмерно длинные адреса пропускаются целиком. URL не обрезается
и не угадывается. Найденная ссылка передаётся `page_find` для чтения; сниппет
может не содержать нужных условий, дат и чисел.

Чтение сохраняет проверку публичного IP, закрепление DNS/TLS, отказ от редиректов
и ограничение загрузки. Текст источника остаётся недоверенными данными. Новое
описание инструмента указывает агенту использовать официальный поиск для
астрономических открытий и читать найденный URL. Выбор действия остаётся за моделью:
локальный тест подтверждает возможность маршрута, а не гарантирует её поведение.

Пять обязательных конфигураций и прежние семь `--bonuses` сохранены. Новый режим
включается явно. Старые отчёты используют конфигурации своего манифеста, поэтому
в архив не добавляется пустая строка нового режима. Новые зависимости включены
в сигнатуры протокола; изменённый код не возобновляет старые замеры.

## Наблюдение инструмента, ответ и оценка факта

Новые результаты источников содержат `diagnostic` версии `source-diagnostics-v1`:

| Поле | Значение |
|---|---|
| `stage` | Валидация, поиск, DNS, загрузка, извлечение или ограничение вывода |
| `outcome` | `ok`, `empty` или `error` |
| `error_kind` | Наблюдаемый класс ошибки; `null` при успехе |
| `http_status` | Полученный код HTTP либо `null`, если он неизвестен |
| `retryable` | Подсказка о допустимости повтора; `null`, если данных недостаточно |

Различаются HTTP-ошибка, таймаут, сбой соединения/TLS/DNS, отклонённый URL,
редирект, challenge, неподдерживаемый тип содержимого, превышение размера,
неверная схема ответа и усечение вывода. Это классы наблюдений, а не обещание
точной первопричины. Например, HTTP 403 не объявляется автоматически антибот-защитой.
Диагностика не сохраняет произвольный текст исключения, заголовки или секреты.
Автоматических повторов не добавлено; лимиты цикла и последний ответ без инструментов
работают как прежде.

Офлайн-аудит хранит отдельно:

- ошибки и пустые результаты инструментов;
- `answer` / `abstention` / `missing` и исходный статус выполнения;
- правильность по `freshqa-quantity-v2`;
- исторические расходы, не смешанные с новыми нулевыми расходами.

Успешная загрузка не доказывает достаточность источника. Сетевая ошибка может
сосуществовать с правильным ответом. `max_steps` также не означает неверный факт.
Неправильный ответ при сетевом сбое не получает автоматически причинный диагноз.

## Что установлено по сохранённым данным

[Аудит](audit.md) покрывает все **725 ответов**, отдельно исходные 125 и собственные
20 вопросов. [JSON](audit.json) содержит сводки, 100 подробных результатов собственных
вопросов, индексы событий и хеши входов.

На собственных 20 вопросах Mini с чтением:

- правильны **2/20**, отказов — **16/20**;
- **40 HTTPError в 12 трейсах**, дополнительно один ReadTimeout в этой же группе;
- любые ошибки инструментов встречаются в **13** трейсах, включая заблокированный повтор;
- прямых вызовов чтения по URL первоисточника — **0**; использовались Wikipedia и чтение по названию.

Коды старых HTTPError не сохранены. Они остаются неизвестными; поздние успешные
проверки доступности не превращают старые ошибки в HTTP 403, 429 или 503.

Несколько конкретных случаев:

- [`fresh-128`](../../../traces/cheap_search_read/fresh-128.json): сетевых ошибок нет,
  но ответ `12 billion years ago` перепутал давность эпохи с возрастом Вселенной
  `1.4 billion years`. Это содержательный промах.
- [`fresh-133`](../../../traces/cheap_search_read/fresh-133.json): сниппет содержит
  `WISPIT 2c`, затем чтение не находит ключевые слова и возникают HTTPError.
  Финал — отказ. Нельзя утверждать, что нужного факта вообще не было в полученных данных.
- [`fresh-135`](../../../traces/cheap_search_read/fresh-135.json): правильный `S301`
  при статусе `max_steps`, что показывает независимость статуса и метрики.
- [`fresh-142`](../../../traces/cheap_search_read/fresh-142.json): три HTTPError,
  один ReadTimeout и отказ; точные HTTP-коды и причинная роль каждого сбоя неизвестны.

У Haiku с чтением транспортные ошибки встречаются и в **четырёх правильных**
ответах на собственные вопросы. Это дополнительная проверка, почему один общий
ярлык «сетевая ошибка = неправильный ответ» не подходит.

## Воспроизвести локальную проверку

Команды из корня проекта, с уже установленными зависимостями:

```bash
PYTHON_DOTENV_DISABLED=1 .venv/bin/python -m freshqa schemas --official-sources
PYTHON_DOTENV_DISABLED=1 .venv/bin/python -m freshqa.source_audit
PYTHON_DOTENV_DISABLED=1 .venv/bin/python -m pytest tests/test_official_sources.py tests/test_official_source_flow.py tests/test_source_configuration.py tests/test_source_diagnostics.py tests/test_source_audit.py -q
```

Схемы и аудит не создают клиента модели и не читают `.env`. Аудит пишет только
в отдельный revision-каталог и сверяет входные хеши. Тесты подменяют HTTP/LLM,
проверяют поиск, фильтр, чтение найденного URL и финальный ответ. Тестовые ответы
не добавляются к измеренным данным.

`ask --official-sources` и `benchmark --configs cheap_official_sources` — входы
для будущего реального опыта; они **не выполнялись**. Перед таким опытом нужны
отдельный каталог, ограниченная выборка и согласованный бюджет. Старые каталоги
для resume новым протоколом не подходят.

## Практические ограничения

Текущая доступность DDG и официальных сайтов не проверялась. Один поисковый backend
может быть недоступен; новое поведение теперь явно сообщает об этом. Поддерживаются
HTML и обычный текст, без выполнения JavaScript и обхода ограничений сайтов.

Новый реальный показатель точности, цена и задержка пока **не измерены**. Старые
**2/20** остаются результатом прежнего агента, а не нового режима. После разрешения
внешних проверок сначала стоит проверить доступность поиска/чтения без модели,
затем провести небольшой отдельный замер. Эти 20 вопросов пригодны для диагностики;
для вывода об общем улучшении понадобится дополнительная выборка.
