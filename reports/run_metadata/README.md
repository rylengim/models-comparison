# Как выполнялся замер

Данные и основной пакет `freshqa` зафиксированы до полного запуска. Все пять
конфигураций используют 145 вопросов, одинаковую метрику и `max_steps=6`.
Параметры, модели и хеши сохранены в [execution.json](execution.json) и
[основном манифесте](../../traces/manifest.json). Хеш датасета в манифесте
вычисляется по каноническому JSON; он отличается от SHA-256 байтов JSONL
в аудите источников.

Сначала последовательно завершены Sonnet 4.6 и GPT-4o mini без инструментов.
После двух HTTP 429 включено ожидание между запросами. Исходные отказы,
прерванная попытка поиска и сверка списаний сохранены в
[provider-rejections](../provider-rejections/README.md).

Оставшиеся три режима выполнялись отдельными процессами. Из корня репозитория:

```bash
python reports/run_paced.py benchmark --resume --configs cheap_search --budget-usd 0.75
python reports/run_paced.py benchmark --traces tmp/final-cheap-read/traces --out tmp/final-cheap-read/report --configs cheap_search_read --budget-usd 1.00
python reports/run_paced.py benchmark --traces tmp/final-medium/traces --out tmp/final-medium/report --configs medium_search_read --budget-usd 2.50
```

В этой параллельной фазе процессы использовали один файл `tmp/openrouter-request-gate.timestamp`,
`flock` и минимальный интервал стартов 2.5 секунды. Настройки можно явно задать
через `FRESHQA_GATE_PATH` и `FRESHQA_GATE_INTERVAL_S`. Обёртка меняет только
расписание запросов, сохраняет payload и не делает автоматических повторов.
При неизвестной стоимости создаётся постоянный `.BLOCKED`; ожидающие процессы
прекращают отправку, уже допущенные запросы могут завершиться. Снять блокировку
можно только после сверки всех списаний. Обычный CLI без обёртки не использует
этот межпроцессный ограничитель.

Порог первого процесса включает расходы уже завершённых двух базовых режимов.
Пилоты и прерванные попытки учитываются отдельно. Сумма порогов процессов —
$4.25; до рабочего общего бюджета $5 оставлен запас. Каждый порог проверяется
между запросами, поэтому последний запрос может его пересечь.

Для объединения результатов требуется остановка всех процессов, одинаковые
`manifest.signature`, все 145 уникальных ID в каждом режиме, известные расходы
и отсутствие неразобранных `inflight`/`BLOCKED`. В основной каталог копируются
только отсутствующие каталоги `cheap_search_read` и `medium_search_read`;
существующие трейсы не перезаписываются. Затем отчёт строится локально из JSON.

## Ограничение измерения времени

Первые 50 завершённых ответов Sonnet получены без обёртки. Остальные ответы
Sonnet, весь `cheap_no_tools` и первые 21 ответ `cheap_search` использовали
локальный интервал 3.5 секунды. Затем три режима с инструментами разделяли
общий интервал 2.5 секунды; последующие изменения указаны ниже. Время в трейсе включает очередь, запросы модели
и инструменты. Его можно использовать как описание фактического выполнения,
но нельзя трактовать как чистое сравнение скорости моделей. На оценку ответа,
число шагов и фактическую стоимость эта очередь непосредственно не влияет.

После четвёртой сверки расходов параллельная фаза остановлена из-за повторных
транспортных сбоев. Диагностика подтвердила `ReadTimeout`; конкретная причина
внешнего тайм-аута не установлена. Продолжение выполнялось одним процессом
за раз с тем же интервалом 2.5 секунды и неизменными запросами. Это ещё одно
различие условий времени, указанного в таблице.

После завершения всех 145 вопросов `cheap_search_read` режим `cheap_search`
продолжен с `fresh-33` одним процессом с `FRESHQA_GATE_INTERVAL_S=1.5`.
[Документация OpenRouter](https://openrouter.ai/docs/api_reference/limits)
не задаёт общий лимит запросов для платных моделей; ограничения upstream
провайдера могут различаться. При отказе сохраняется остановка и ручная сверка,
а не автоматический повтор. Пауза не меняет payload или лимит шагов.

С `cheap_search/fresh-42` обёртка переиспользует одну HTTPS Session на процесс.
Это сокращает число новых TLS-рукопожатий; последний подтверждённый тайм-аут
произошёл в `ssl.do_handshake`. Для обоих адаптеров явно задан `max_retries=0`;
Session закрывается при выходе. Таймаут `(10, 90)`, тело запроса, модель,
основной пакет и оценка неизменны. Диагностика печатает только классы ошибок,
имена модулей/функций и время POST, без ключей и текста запросов.
Изменение транспорта также учитывается как ограничение сравнения времени.

После исправления транспорта оставшиеся `cheap_search` и `medium_search_read`
(последний с `fresh-16`) снова выполнялись параллельно. Оба используют
`FRESHQA_GATE_INTERVAL_S=1.5`, один файл gate и отдельную постоянную Session.
Это две разные платные модели; общий limiter и глобальная блокировка при
неизвестной стоимости сохраняются. Лимит Haiku — $2.50, основного каталога —
$0.75; завершённый режим с чтением и пилоты учитываются отдельно.

После полного `cheap_search` и сверки 7 оставшийся Haiku продолжен
с `fresh-91` одним процессом, `FRESHQA_GATE_INTERVAL_S=3.5`. Причина —
HTTP 429 на втором запросе этого вопроса. Первая оплаченная часть
архивирована и включена в расходы восстановления; модель, промпты,
данные, лимит шагов и основной пакет не менялись.

## Завершение

Все пять режимов завершены: 725 ответов, 2107 LLM-вызовов в завершённых
попытках. После остановки процессов проверены манифесты, хеши, ID, оценки
и суммы событий. Две итоговые сверки key/credits совпали: $1.75129015,
включая пилоты и восстановление. Каталоги двух рабочих процессов скопированы
в основной `traces` без перезаписи существующих файлов; отчёт построен локально.
[Аудит](final_trace_audit.json), [полный учёт](../expenditure.md).
